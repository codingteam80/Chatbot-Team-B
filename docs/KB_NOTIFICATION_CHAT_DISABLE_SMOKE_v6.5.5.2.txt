DocuBot v6.5.5.2 - KB Notification + Chat Disable UX Smoke
======================================================================
Scope
-----
UI-only hotfix on exact v6.5.5.1 baseline.
No retrieval, generation, embedding, reranking, chunking, Top-K, or KB-lifecycle changes.

Expected success notification
-----------------------------
Knowledge Base is successfully updated.
Added: <N> · Updated: <N> · Deleted: <N>

The success toast should:
- show a success icon;
- render the title and counts cleanly (no awkward two-column wrapping);
- remain an overlay and not move the welcome/chat layout;
- hide technical chunk/Qdrant/BM25/semantic-index/KB-health details.

Expected chat behavior during Update Knowledge Base
--------------------------------------------------
- textarea/editor is disabled while the KB worker is running;
- send button is disabled while the KB worker is running;
- Enter cannot submit a message while the worker is running;
- server-side submit guard also rejects chat submission during the update;
- composer remains in the same position and is automatically re-enabled after the update.

Manual check
------------
1. Make one harmless change to a test knowledge file.
2. Confirm and click Update Knowledge Base.
3. While it runs, verify the chat editor is visibly disabled and cannot be edited/submitted.
4. When it completes, verify the chat editor is enabled again.
5. Verify the toast is readable and only shows Added/Updated/Deleted counts.
