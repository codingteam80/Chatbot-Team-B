DocuBot v6.5.5 — Goal Completion Smoke / Manual Verification
======================================================================

PURPOSE
-------
This release closes the remaining implementation gaps without changing the
certified retrieval architecture or rebuilding the production KB at install.

A. UI STABILITY DURING UPDATE KNOWLEDGE BASE
--------------------------------------------
1. Make one harmless source change under data\technical_documents.
2. Start DocuBot normally.
3. Confirm the maintenance area remains at the top.
4. Confirm the checkbox is visible for BOTH incremental and full-rebuild modes.
5. Confirm Update Knowledge Base is disabled until the checkbox is checked.
6. Click Update Knowledge Base once.
7. While the worker runs, confirm:
   - the warning + checkbox + button remain in the same top region;
   - the welcome/chat composer remains in its normal position;
   - no spinner/status row pushes the composer down or pulls it upward;
   - the checkbox/button are protected from a second launch.

B. KB LIFECYCLE — ACTUAL ADD / MODIFY / DELETE
-----------------------------------------------
Run from the VS Code terminal only when get_update_plan is currently noop:

    venv\Scripts\python.exe scripts\test_incremental_kb_lifecycle_live.py

The script creates one uniquely named temporary TXT, validates incremental add,
modify and delete, then returns the KB to the original clean state. It has a
finally/recovery path and never runs during patch installation.

C. RETRIEVAL-ONLY GATE
----------------------
Run:

    venv\Scripts\python.exe scripts\run_v6_5_5_completion_suite.py --skip-llm

The seed-6501 benchmark is test-only. Expected Rule/Directive references are not
imported by production runtime. The retrieval report measures:
- recall;
- final-reference precision;
- pair semantic consistency;
- per-query latency;
- MultiQuery used vs skipped because single-query semantic+BGE was proven.

D. LLM-FROM-VERIFIED-CONTEXT GATE
---------------------------------
After retrieval passes, run the full completion suite:

    venv\Scripts\python.exe scripts\run_v6_5_5_completion_suite.py

LLM generation is blocked for any case whose retrieval/precision gate failed.
It checks expected structured reference grounding, Yes/No polarity where the
source determines it, competing references, fallback, and generation latency.

E. ONE COMMAND INCLUDING LIVE KB LIFECYCLE
------------------------------------------
Only from a clean noop KB baseline:

    venv\Scripts\python.exe scripts\run_v6_5_5_completion_suite.py --with-live-kb-lifecycle

The completion report is written under:
    logs\v6_5_5_completion\completion_*.json

F. ARCHITECTURE INVARIANTS
--------------------------
Generation  : qwen2.5:7b
Embedding   : qwen3-embedding:8b
Reranker    : BAAI/bge-reranker-v2-m3
Retrieval   : BM25 + Qdrant -> RRF -> BGE
Top-K       : 10 / 10 / 3
Threshold   : 0.55
Chunking    : 900 / 150
MultiQuery  : original + exactly 2 alternatives when ambiguity requires it

No phrase-to-Rule mapping is introduced by this release.
No production Qdrant/BM25 rebuild is performed by the installer.
