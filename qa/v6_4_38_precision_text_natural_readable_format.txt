v6.4.38 changes
---------------
1. Text-only natural MISRA concept recovery
   - Explicit human descriptions can produce source-language requirement cues
     even when no C snippet is pasted.
   - The remaining missing-return-path manual fallback now resolves to the
     authoritative Rule 17.4 body.
   - Without a visible function signature/control flow, the per-rule state is
     "Needs more context" rather than an invented confirmed violation.

2. Per-rule assessment precision
   - Rule 18.1 vs Rule 18.4:
     * array declarations are no longer misread as array accesses;
     * a visible array-backed pointer moved by a known in-range constant offset
       can mark Rule 18.1 as satisfied while Rule 18.4 remains potential
       non-compliance for explicit pointer arithmetic.
   - Rule 13.5:
     * visible assignment/inc/dec on the RHS of &&/|| remains potential
       non-compliance;
     * an RHS function call with unknown behavior is "Needs more context"
       unless a persistent side effect is actually proven by the visible input.

3. Readable ChatGPT-style natural MISRA presentation
   - User-facing natural compliance answers now use:
       Assessment
       Applicable/Relevant MISRA Rule(s)
       Status
       Requirement
       Why it applies
       concise Rationale/Source exception when useful
       Conclusion
   - Multiple rules are numbered and itemized.
   - Raw Analysis / Applies-to metadata is no longer visibly dumped in normal
     natural compliance answers.
   - Exact Rule/Directive explanation requests (for example "Explain Rule 1.2")
     stay on the existing source-shaped certified format.
   - Source cards/citations remain rendered separately by the existing UI.
