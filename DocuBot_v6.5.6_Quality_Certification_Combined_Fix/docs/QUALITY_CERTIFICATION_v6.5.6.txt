DocuBot v6.5.6 — Quality Certification
================================================================================

Purpose
-------
Close the remaining quality goals together without changing the production
retrieval/answer/KB-update algorithms before measurement proves a runtime defect.

The certification sequence is:
1. Static preservation validation.
2. KB Health pre-check.
3. Actual temporary add/modify/delete KB lifecycle and clean-state restoration.
4. Same-meaning retrieval benchmark (Recall/Precision/Top-1/semantic consistency).
5. Answer generation only from retrieval cases that already passed.
6. Deterministic claim-grounding/reference/polarity checks.
7. Combined warm-path normal-question latency check against 25 seconds per case.
8. Final KB Health check.
9. Evidence ZIP + SHA256.

Safety
------
The live delete test refuses to run unless Smart Build reports a clean NOOP baseline.
It uses one uniquely named temporary text file and removes it in a finally/recovery
path. After deletion it verifies the probe is absent from the manifest, Qdrant and
BM25, while baseline document hashes/last-indexed states, per-file chunk counts and
the MISRA semantic Rule-index hash remain unchanged.

Run
---
Close the DocuBot Streamlit/server process first, then run:
Run_v6.5.6_Quality_Certification.bat

Default benchmark
-----------------
Seed: 6506
Concept pairs: 6
Questions: 12 (two meaning-equivalent variants per concept)
Normal-question target: <= 25 seconds combined retrieval + answer generation per case.

For the full 12-pair / 24-question bank, run:
  venv\Scripts\python.exe -X utf8 -m scripts.run_v6_5_6_quality_certification --full-bank
